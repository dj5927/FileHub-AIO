# FileHub AIO 인터넷 QR 설정 전송 중계 서버

LAN 자동 전송과 별개인 **서로 다른 네트워크 간 QR 설정 전송**에 사용하는
작은 HTTPS 중계 서버입니다. 개인 시놀로지 NAS 등에 자체 배포하도록 제작했습니다.

## 구조와 개인정보 처리

- **받는 TV:** QR 표시 → 일회용 세션 생성 및 암호화 키 보유 → 서버에 2분간 수신 요청
- **보내는 휴대폰:** TV QR 스캔 → FileHub 링크 열기 → 양쪽 **확인 코드 6자리 대조** → 설정 암호화 후 전송
- **받는 TV:** 암호화 데이터 수신·복호화 → 내용 확인 후 **병합/교체 수동 승인**
- HTTPS 서버가 볼 수 있는 데이터는 임의 식별자, 일회용 인증 토큰의 해시,
  **AES-256-GCM 암호문**입니다. **복호화 키와 평문 NAS 비밀번호/클라우드 토큰은 전송하지 않습니다.**
- 서버는 세션을 **2분 뒤 만료**, 한 번 수신하면 즉시 제거하며
  **메모리에만 저장**합니다(재시작 시 모두 사라짐).
- 서버에 기본 관리자 계정이나 API 키가 없으므로 **공개 배포 시 트래픽 제한,
  TLS 인증서, 방화벽, HTTPS 역방향 프록시가 반드시 필요**합니다.
- QR 스크린샷이나 일회용 링크를 타인과 공유하지 마세요. QR을 소유한 사람은
  전송 권한과 복호화 키를 함께 가집니다.

## 시놀로지 NAS 설치 (Container Manager)

1. 시놀로지 Container Manager가 실행되는 NAS에 relay 폴더를 복사합니다.
2. Container Manager → 프로젝트 → 새 프로젝트에서
   docker-compose.yml을 사용해 컨테이너를 생성합니다.
   또는 SSH에서 relay 디렉터리에서 docker compose up -d --build를 실행합니다.
3. NAS에서 http://127.0.0.1:31887/health를 열면
   {"status":"ok"}를 받아야 합니다.
4. DSM **로그인 포털 → 고급 → 역방향 프록시**를 설정합니다.
   - 소스: 공개 **HTTPS**, 예) relay.example.com:443
   - 대상: NAS 내부 http://127.0.0.1:31887
   - Let's Encrypt 등 **유효한 TLS 인증서**를 적용합니다.
   - 외부에서는 **HTTPS 443만** 연결하도록 하고, 컨테이너의
     31887 포트를 외부에 개방하지 않습니다.
   - 외부 443 연결을 사용할 수 없는 환경(CGNAT 등)이라면
     별도의 인증된 HTTPS 터널/프록시가 필요합니다.
5. 외부 모바일 데이터로 https://relay.example.com/health를 호출해
   정상 응답을 받는지 확인합니다.
6. **TV FileHub → 원격 저장소 → 설정 파일 내보내기·가져오기 → 인터넷 QR 전송
   → 중계 서버 HTTPS 주소 설정**에서 그 공개 주소를 저장합니다.

## FileHub 사용

1. TV에서 **인터넷 QR 전송 → QR 표시·받기**를 누릅니다.
2. 휴대폰은 다른 Wi-Fi/모바일 데이터에서도 카메라로 TV QR을 찍고
   HTTPS 페이지의 **FileHub에서 열기**를 누릅니다.
   페이지로 전송되는 것은 /pair 경로뿐이고 일회용 키는 URL fragment에
   남아 브라우저가 서버로 보내지 않습니다.
   FileHub에서 **확인 코드**를 대조 후 **암호화 전송**합니다.
3. TV에서 **병합** 또는 **전체 교체**를 선택해야 실제 반영됩니다.
4. 브라우저에서 FileHub 앱으로 연결되지 않으면,
   웹페이지의 **연결 주소 복사**를 누른 다음 휴대폰 FileHub의
   **인터넷 QR 전송 → QR 스캔·보내기** 화면에서 붙여넣을 수 있습니다.

**LAN 자동 전송은 별도 메뉴로 그대로 동작**하며 이 중계 서버가 필요하지 않습니다.

## 개발 및 검증

- Node.js 20 이상: npm test, npm start
- 외부 패키지 의존성 없음, Node 내장 http / crypto만 사용
- 기본 내부 포트: 31887
- GET /health는 상태 정보만 반환
- 공개 HTTPS API:
  - POST /v1/sessions — 임의 세션 ID/한 번 쓰는 읽기·쓰기 권한 생성
  - POST /v1/sessions/:id/payload — 일회용 쓰기 권한으로 암호문 업로드
  - GET /v1/sessions/:id/payload — 일회용 읽기 권한으로 암호문 수신 후 즉시 삭제
  - DELETE /v1/sessions/:id — TV 소유자 권한으로 취소
- 세션 64개, 암호문 총 16MiB, 개별 설정 전송 최대 4MiB,
  IP당 분당 30회 생성 제한

## 배포 전 주의

이 저장소에는 **서버 소스와 시놀로지 배포 설정만** 포함되어 있습니다.
공개 HTTPS 중계 서버는 사용자가 실제 운영 환경에 설치해야 합니다.
중계 서버를 설정하지 않은 앱에서 QR 전송을 시도하면 안내 메시지가 표시됩니다.
앱 서명키, NAS 관리자 암호, Cloudflare 자격증명 등을 GitHub에 게시하지 마세요.
