# NAS Mount v1.3.78 — 안전 종료 복원 / Google Drive 콜드 연결 지연 완화

## 변경한 방향

사용자 요청은 "프로그램을 종료하면 드라이브도 실제로 안전 해제하고, 다시 실행한 뒤 매번 빠르게 연결"하는 것입니다. v1.3.77의 **화면만 종료하고 엔진/드라이브 연결을 남기는 기능은 잘못 구현한 방향**이므로 **모두 제거**했습니다. 안정적인 v1.3.76 메인 UI, 안전 종료, 파일잠금 브리지를 기준으로 새 소스를 작성했습니다.

- 트레이 메뉴 **프로그램 종료**를 누르면 기존처럼 모든 연결의 업로드 상태를 확인하고 rclone/WinFsp 드라이브를 안전하게 해제한 뒤 프로그램을 종료합니다. 종료에 실패하면 사용자에게 알리고 드라이브를 강제로 해제하지 않습니다.
- 제목표시줄 X는 기존대로 트레이에 숨깁니다. 별도의 상주 엔진이나 "연결 유지하고 화면 종료" 기능은 없습니다.
- 다시 실행하면 **새 rclone 프로세스로 실제 Google Drive 파일시스템을 연결**합니다. 탐색기 폴더 목록과 디스크 용량 검증을 통과해야 녹색 연결 완료로 표시합니다.

## 확인된 Google Drive 지연 단서

사용자 로그: 동일한 Google 프로필의 실제 연결이 약 2.15초 또는 34.77~36.06초로 불규칙하게 변화합니다. 느릴 때에도 드라이브 준비 완료 후 폴더 조회는 약 0.3초였습니다. 한 차례 정밀 진단에서는 `rate_limit`, `api_retry_or_pacer`가 실제 발생했습니다.

rclone v1.76.0 Google Drive 기본 옵션은 `pacer_min_sleep=100ms`, `pacer_burst=100`. Google API 요청이 집중되면 공유 OAuth 클라이언트의 쿼터와 Google 측 속도 제한/재시도에 걸릴 가능성이 있습니다. Google에만 `--drive-pacer-min-sleep 250ms --drive-pacer-burst 2`를 적용해 최초 요청 폭주를 완화했습니다. **다른 NAS/OneDrive/TeraBox 등에는 적용하지 않았습니다.** Google 클라이언트 ID와 계정 인증정보는 변경하지 않았습니다.

추가로 Google의 액세스 토큰 만료 여부를 연결 직전과 연결 완료 직후 로그에 **참/거짓만** 남깁니다. 원본 토큰, 갱신 토큰, 이메일, 파일명, URL은 출력하지 않습니다. 사용자의 설정 파일은 테스트 전에 만료된 액세스 토큰이 남아 있었으므로 이 기록은 원인 분석에 도움이 됩니다.

## 실제 Google API 읽기 전용 비교 결과

원본 프로필의 OAuth 설정을 **일회용, 현재 사용자만 읽을 수 있는 임시 폴더에 복사**한 다음 `rclone lsf`로 루트만 조회했습니다. 실제 Google Drive 파일을 변경하지 않았고 파일 목록을 로그에 남기지 않았습니다. 테스트용 설정 사본은 즉시 삭제했습니다. 각 비교에서 사본의 액세스 토큰은 만료된 상태로 시작했습니다.

| 모드 | 측정된 완료시간 |
| --- | --- |
| rclone 기본값 (첫 측정) | 19.09초 |
| Google API 요청 제한 250ms / burst 2 (첫 측정) | 1.23초 |
| rclone 기본값 + 앱 동일 TYPE 환경 변수 | 1.31초 |
| 요청 제한 + 앱 동일 TYPE 환경 변수 | 1.20초 |
| 요청 제한 반복 측정 | **9.91초** |

**해석:** 제한 설정은 몇 차례 빠르게 완료됐지만, 같은 설정에서도 9.91초가 발생했습니다. 즉, 개선 효과가 확정적으로 재현된 것은 아니며, Google 서버 응답·공용 OAuth 쿼터의 불규칙성도 여전히 존재합니다. **이 버전을 RaiDrive처럼 항상 2~3초라고 보장하면 안 됩니다.**

rclone의 기본 Google OAuth 클라이언트는 사용자가 공유하는 프로젝트 쿼터를 사용합니다. 사용자별 개인 클라이언트 ID를 입력하지 않고도 RaiDrive는 제조사 등록 앱으로 로그인할 수 있지만, 그 앱도 Google API 자체는 사용합니다. 다른 앱의 비공개 OAuth ID/Secret을 가져오거나 권한 없이 복제하지 않습니다.

## 검증 및 사용

1. v1.3.77을 실제로 설치했다면 트레이의 **모든 연결 안전 해제 후 종료** 메뉴로 모든 드라이브를 정상 종료하세요. Excel 파일 및 업로드를 먼저 마쳐야 합니다.
2. 새 `NASMount_1_3_78_GOOGLE_COLD_START_FULL.zip`을 **새 폴더에 전체 압축 해제** 후 실행하세요. 기존 실행 파일 위에 EXE만 덮어쓰면 안 됩니다.
3. 연결 직후 로그에서 `GOOGLE_MOUNT_API_PACING`, `GOOGLE_STORED_ACCESS_TOKEN_BEFORE_START`, `GOOGLE_STORED_ACCESS_TOKEN_AFTER_CONNECT`, `PROFILE_OPERATION_TIMING`을 확인할 수 있습니다. 각 기록에는 토큰 본문이 포함되지 않습니다.
4. 정상 종료·재실행을 여러 번 반복하여 실제 Google Drive 시간이 개선되었는지 비교해 주세요. 같은 방식의 로컬 루트 조회는 API 서버 상태에 따라서도 변동하므로 3회 이상 반복이 유용합니다.

기존 Excel 소문자 확장자 유지 v1.3.76 파일잠금 브리지, 안전 해제, 파일 업로드 확인, WinFsp 네트워크 드라이브 등록은 유지했습니다. 기존 rclone/WinFsp 구성요소 버전은 변경하지 않았습니다.
