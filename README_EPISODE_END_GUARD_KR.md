# NAS Mount Android v0.1.30 — 영상 종료 후 다음 편 확인창 수정

## 현상

- v0.1.29에서 영상 재생바의 이전/다음 편 수동 전환은 정상.
- 사용자 실기기 보고: 약 20분짜리 에피소드가 끝나도 재생 시각이
  20분 01초, 20분 02초처럼 계속 증가하고, 자막이 남는 것처럼 보이며
  **다음 편 재생 확인창은 나타나지 않음**.

## 원인 분석

- 기존 `VideoPlayerActivity`의 다음 편 확인창은
  `Player.Listener.onPlaybackStateChanged(STATE_ENDED)`에서만 호출됐다.
- Media3는 단일 동영상의 영상/오디오/자막 렌더러 또는 스트리밍 소스가
  모두 종료되어야 `STATE_ENDED`로 전환된다. 자막 렌더러나
  원격 스트림이 오래 살아 있으면 영상이 끝나도 재생 상태가
  `STATE_READY` 또는 `STATE_BUFFERING`으로 남을 수 있다.
- 기기 로그를 확보하지 못했으므로 특정 파일에서 어느 렌더러가 실제
  종료를 지연시켰는지는 **추정 원인**이며 미확정이다.

## 해결

- 기존 `STATE_ENDED` 경로는 유지하고, 신규 `PlaybackEndGuard`가
  300ms 간격으로 **Media3가 보고한 총 재생 길이와 현재 재생 위치**를
  비교해 영상 종료 신호 누락을 보완한다.
- 일시정지 중/초기 이어보기 확인 중/유효하지 않은 영상 길이에서
  자동 다음 편 팝업이 뜨지 않도록 차단한다.
- 표시된 영상 종료 시각 근처(마지막 120ms 이내)에 도달한 상태가
  300ms 이상 지속되어야 종료를 확정한다.
- 종료 시 `player.pause()`하여 자막·오디오 및 재생시간이
  계속 진행되는 현상을 중지하고, 이어보기 기록을 지운다.
- 다음 편이 있으면 기존 `다음 편을 재생할까요?` 확인창을 표시;
  사용자가 확인하면 다음 편으로 이동. 마지막 편은 팝업 없이 종료.
- 종료를 이미 처리한 뒤 원래 `STATE_ENDED` 이벤트가 발생해도
  확인창을 다시 띄우지 않는다.
- 종료를 임의로 처리한 경우 `onPause/onStop`에서 이어보기 기록이
  새로 생기지 않도록 종료 Guard 결과를 확인한다.
- 수동 이전/다음 버튼 및 같은 폴더 자연순 영상 정렬은 기존과 동일.

## 검증

- v0.1.29 전체 소스 복제 후 v0.1.30 / versionCode 31로 릴리스.
- `:app:testDebugUnitTest :app:lintDebug :app:lintVitalRelease
  :app:assembleRelease --offline --no-daemon --max-workers=2` 통과.
- 총 JUnit **217/217 성공**. 새 `PlaybackEndGuardTest` 10개 포함:
  정상 `STATE_ENDED`, 길이 초과 재생, BUFFERING에서 종료 누락,
  길이 미확정, 중단 상태, 되감기, 일시정지 상태, 이어보기 확인 중
  오작동 방지, 마지막 시각 직전의 조기 전환 방지, 확인창 중복 방지.

## 추가 확인 필요

- Galaxy Fold7에서 문제가 있었던 **동일 20분짜리 실제 영상**의 끝부분을
  직접 재생해 새 다음 편 확인창과 시각 정지를 검증해야 한다.
- 현재 개발 Windows PC에 ADB로 연결된 Android 기기가 없어
  실기기에서 렌더러·파일 종류별 종료 행동까지 검증할 수 없다.
- 파일 자체의 재생 길이 메타데이터가 잘못됐다면 여전히 보완이 필요할
  수 있다. 추후 동일 현상이 남을 경우 재생 위치/길이/상태 로그를 수집해
  영상 트랙 기준 종료 판정을 더 강화한다.
- v0.1.29의 다른 기능(문서 편집기, APK 설치, NAS 쓰기, 재생목록,
  상단 UI 등)과 PC beta 상태는 그대로 유지.
