# FileHub AIO Android v0.1.102 — WebDAV DDNS 별칭 TLS 호환성

## 문제와 원인

- 실제 NAS는 동일하더라도 사용자마다 iptime.org, synology.me,
  자체 도메인 및 다른 DDNS 업체의 주소로 연결할 수 있습니다.
- 주소를 보고 NAS 제조사를 판별하거나 포트 5006을 Synology
  전용으로 취급해서는 안 됩니다.
- WebDAV HTTPS에서 서버가 유효한 공인 인증서를 제시해도
  접속 주소가 인증서 이름과 다른 별칭인 경우, 기존 OkHttp의
  기본 이름 검사 때문에 Android 접속이 실패할 수 있었습니다.
- Android는 Windows WinFsp LockBridge를 사용하지 않으므로,
  PC의 Excel '다른 사용자 사용 중' 오표시 문제와는 다릅니다.
  Android에서는 HTTPS 연결 실패가 발생할 수 있습니다.

## 변경

- WebDAV 파일 목록, 다운로드, 영상 스트리밍, 파일 업로드,
  이름 변경, 폴더 생성 및 삭제 요청에 동일한 전송 클라이언트
  정책을 사용합니다.
- Android 플랫폼의 기존 인증서 발급기관 신뢰 체인은 유지하고
  서버 인증서가 유효하며 실제 사용자가 입력한 WebDAV 호스트와
  연결된 경우, DDNS 별칭으로 인한 인증서 이름 불일치만
  WebDAV 경로에서 허용합니다.
- 사용자가 명시적으로 입력한 NAS 관리 API 주소(Synology/QNAP
  공유 링크)의 HTTPS에도 별도로 같은 규칙을 적용합니다.
- 다른 서버 주소로의 이름 불일치 예외, 인증서 미제공 또는
  신뢰하지 않는 발급기관 인증서는 허용하지 않습니다.
  Google/TeraBox/Naver MyBox 등 클라우드 API HTTPS 설정은
  기존대로 유지합니다.
- **주의:** 도메인 별칭은 서버 신원을 암호학적으로 보증하지
  않으므로, 가장 안전한 구성은 접속 주소가 포함된 유효한
  인증서(SAN)를 NAS에 설치하는 것입니다. 서명 체인이 유효한
  임의의 다른 서버 인증서라는 사실만으로 원래 NAS와
  동일한 서버임을 완전히 증명할 수는 없습니다.
- 테스트 WebDavTlsAliasPolicyTest: 사용자 설정 호스트,
  여러 DDNS 업체와 자체 도메인, 잘못된 다른 호스트,
  인증서 누락, HTTP 및 타 프로토콜에 대한 경계 조건.

## 검증 및 설치

- 소스 기준: Android main v0.1.101 위에 변경을 추가하여
  v0.1.102(versionCode 103)로 빌드합니다.
- 실제 Android 단말에서 문제의 DDNS 주소로 WebDAV 열기,
  업로드 및 NAS 공유 링크 생성을 확인해야 최종 동작을
  검증할 수 있습니다. 실기기 연결 결과는 별도입니다.
- PC용 변경은 GitHub의 PC 전용 브랜치에서 별도 배포됩니다.
