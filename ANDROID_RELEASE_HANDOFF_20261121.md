## Android Steam Deck SFTP host-key TransportException fix v0.1.108 (2026-11-22)
- User symptom: Android FileHub opens SFTP profile named Steam Deck but throws generic TransportException. Same server works from FileZilla. Screenshot by itself does NOT disclose nested SSH cause; cannot assert live Steam Deck connection success without device access.
- Source root cause identified: RemoteProvider.ssh HostKeyVerifier.verify threw IllegalStateException wrapping UntrustedHostKey for a new server and SecurityException for a changed host. SSHJ runs verifier in transport/reader context and may surface only net.schmizz.sshj.transport.TransportException to worker/UI. New SftpHostKeyTrust verifier returns false without throwing on transport reader thread, retains volatile fingerprint or pin mismatch; after SSHClient.connect fails, code translates to UntrustedHostKey (shows existing explicit first connection SHA256 fingerprint confirmation) or strict changed-host SecurityException (blocks).
- Additional known Android SSHJ problem: https://github.com/hierynomus/sshj/issues/1032 (Android Conscrypt OpenSslEdDsaPublicKey encoding in SSHJ with modern ssh-ed25519 host keys, Feb 2026). SftpHostKeyTrust recognizes Ed25519/EdDSA public key X.509 SPKI bytes with exact Ed25519 RFC 8410 header/32-byte raw key and builds OpenSSH ssh-ed25519 fingerprint blob; does not bypass SSH signature validation or pinning. RSA/ECDSA continue SSHJ native encoding, unit tested RSA.
- MainActivity.safeError now distinguishes SFTP new/changed host key, user/password authentication, SSH algorithm negotiation and Android Ed25519 failure without dumping potentially sensitive hostnames, paths or credentials; old NAS Mount error dialog heading replaced with FileHub AIO.
- New SftpHostKeyTrustTest includes provider-agnostic EdDSA X509 wrapper, first-use confirmation, trusted fingerprint, mismatch rejection, malformed Ed key failure and RSA existing support. Full Android Gradle test suite 560/560 passed, versionCode 109, versionName 0.1.108.
