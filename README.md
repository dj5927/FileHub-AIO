# FileHub AIO PC for Windows

Windows 10/11용 NAS·클라우드 드라이브 마운트 프로그램입니다.

## 버전과 업데이트

- PC 버전: v1.3.95, 이후 v1.3.96 / v1.3.97...
- PC 전용 GitHub 릴리즈 태그: pc-v1.3.95 / pc-v1.3.96 ...
- Android 버전: v0.1.x — Windows 업데이트와 별개로 운영
- 프로그램 실행 시 트레이 업데이트 알림 / 환경 설정 → PC 업데이트 확인
- 새 PC 버전을 받으면 GitHub 릴리즈 ZIP SHA-256 검증 → 사용자의 설치 승인 → 원격 드라이브 안전 해제 → 프로그램 업데이트 후 재실행
- 업데이트를 강제로 설치하거나 사용자의 원격 데이터를 임의 삭제하지 않습니다.

## 설치

GitHub Releases에서 FileHub-AIO-PC-1.3.95-win-x64.zip 같은 Windows 전용 ZIP을 받습니다. 압축을 별도 폴더에 풀고 FileHubAIO.exe를 실행합니다. 기존 v1.3.83~v1.3.94에서는 PC 업데이트 확인으로 v1.3.95를 설치할 수 있습니다.

업데이트 설치 전에는 Excel/Word 등 열린 문서를 모두 저장하고 닫아야 합니다. 안전하게 해제하지 못한 NAS 드라이브가 있으면 프로그램 교체를 중단합니다. 이전 버전은 사용자 백업 폴더에 보관합니다.

## 포함 엔진 및 출처

- .NET 10 (Windows x64 자체 포함 빌드)
- rclone v1.76.0: https://github.com/rclone/rclone
- rclone-extra v1.76.0-extra (TeraBox): https://github.com/gulp79/rclone-extra
- WinFsp v2.1.25156 (2025 정식판, 공식 서명 MSI): https://github.com/winfsp/winfsp/releases/tag/v2.1

GitHub Actions는 공식 릴리즈 파일과 컴파일된 실행 파일의 SHA-256을 검사한 후 Windows 전체 패키지를 작성합니다. 제3자 엔진의 저작권/라이선스는 각 원본 프로젝트에 따르며, WinFsp에서 파생된 예제의 원 저작권 고지를 유지합니다.

## 소스 빌드

PowerShell에서 dotnet restore NASMount.csproj, dotnet publish NASMount.csproj -c Release -r win-x64 --self-contained true -o publish, dotnet publish LockBridge/LockBridge.csproj -c Release -r win-x64 --self-contained true -o bridge 를 순서대로 실행합니다.

두 프로젝트를 컴파일하는 것만으로 전체 배포본이 완성되는 것은 아닙니다. rclone, 확장 엔진, WinFsp 배포 파일은 GitHub Actions에서 공식 릴리즈로부터 수집합니다.

## 검증 범위

업데이트 무결성, 버전 필터링, 로컬 WinFsp 저장, 백업/롤백에 대한 자동 검사를 포함합니다. 실제 사용자 NAS의 다중 PC Excel 동시 편집 및 서버별 잠금 호환성은 별도 시험이 필요합니다.

## v1.3.85 시놀로지 공유 링크

- 환경 설정의 Synology 공유 링크 생성 / 관리, 또는 NAS 연결 카드의 추가 메뉴에서 엽니다.
- 최초 1회 DSM HTTPS 주소 (예: https://nas.example.com:5001), DSM 계정 및 최상위 공유 폴더 (예: /video)를 지정하세요. 각 FileHub AIO 드라이브에 별도로 설정됩니다.
- DSM 비밀번호는 Windows 자격 증명 관리자에 보관하며, 설정 JSON에는 비밀번호나 OTP를 넣지 않습니다.
- 2단계 인증이 필요하면 OTP 6자리를 입력합니다. Secure SignIn 푸시 승인 전용 계정은 별도 호환 확인이 필요합니다.
- 링크 생성 시 만료 1/3/7/30일·무제한, 선택적 암호를 지원합니다. 링크를 복사하거나 관리 목록에서 조회·선택 해제할 수 있습니다.
- 탐색기 메뉴 등록은 사용자가 버튼을 누를 때만 HKCU에 추가됩니다. Windows 10에서는 우클릭 메뉴, Windows 11에서는 우클릭 → 추가 옵션 표시(Shift+F10)에서 사용합니다. 기본 메뉴 강제 변경이나 Explorer 재시작은 없습니다.
- 선택된 경로는 FileHubAIO.exe의 --synology-share 명령행 인수로 전달합니다. 원본 파일을 외부 중계 서버로 업로드하지 않습니다.
- DSM 설정은 %APPDATA%/NASMount/synology-sharing.json에 저장됩니다. 기존 설정 내보내기/가져오기 파일에는 아직 포함되지 않아 다른 PC에서는 다시 설정해야 합니다.
- 실제 DSM 버전별 공유 발급, 외부 링크 다운로드 및 2FA 동작은 사용자 NAS에서 별도 검증이 필요합니다.

## v1.3.85 PC 업데이트 하단 알림

- 앱 시작 직후 NAS 연결 상태와 무관하게 GitHub PC 전용 릴리즈를 확인합니다.
- 새 버전이 있으면 메인 화면 오른쪽 하단에 노란색 PC 업데이트 있음 v... 링크를 표시합니다. 최신 버전이면 숨깁니다.
- 링크를 누르면 다운로드·SHA-256 검증을 즉시 시작하고, 원격 드라이브 안전 해제와 프로그램 교체 직전에 사용자 승인을 요청합니다.
- Android 릴리즈를 PC 업데이트로 취급하지 않습니다.

## v1.3.90 WinFsp 수동 드라이버 업데이트 알림

- 실제 설치된 WinFsp DLL 파일 버전과 배포본의 2.2.26286을 비교합니다. 2026-11-18 테스트 PC에서는 구버전 2.2.26215 (Beta4)를 정상 검출했습니다.
- 구버전인 경우 메인 우측 하단 첫째 줄에 주황색 "WinFsp 2.2.26215 · 설정에서 WinFsp 확인/설치 수동 업데이트 필수"를 표시하고, 누르면 환경 설정을 엽니다.
- 파일 버전을 읽지 못할 때만 "WinFsp 버전 확인 불가 · 11/18 이전 설치자는 수동 업데이트 필수"를 표시합니다. 설치 날짜만으로 실제 드라이버 버전을 단정하지 않습니다.
- 드라이버가 없으면 설치 안내, 2.2.26286 이상이면 경고를 숨깁니다.
- 둘째 줄의 기존 노란색 "PC 업데이트 있음" OTA 알림은 그대로 유지합니다. PC 앱 OTA는 Windows 시스템 드라이버를 자동 교체하지 않습니다.
- 앱 시작, 창 재활성화, WinFsp 설치 종료 후 알림을 새로 읽습니다. 수동 설치 전 Office 파일을 저장하고 NAS 드라이브와 다른 WinFsp 프로그램을 안전하게 해제해야 합니다.

## v1.3.91 WinFsp 정식판 복귀 · RaiDrive 보호 (v1.3.90 안내 대체)

- RaiDrive에서 2026년 WinFsp Beta5 적용 후 동작 오류가 보고되어,
  FileHub 포함 드라이버를 WinFsp 2025 정식 2.1.25156으로 복귀했습니다.
  동일 버전의 winfsp.net 2.1.25156을 사용합니다.
- GitHub 빌드는 공식 서명 MSI의 SHA-256을 검증하며 PC OTA는
  Windows 시스템 드라이버를 자동 교체하지 않습니다.
- WinFsp 2.2 Beta가 설치됐다면 FileHub에서 정식판 MSI를 강제
  덮어쓰지 않습니다. 열린 파일 저장 → FileHub 및 RaiDrive 드라이브
  안전 해제 → 두 프로그램 및 다른 WinFsp 이용 앱 종료 →
  Windows 설정의 설치된 앱에서 WinFsp 2026 Beta 수동 제거 →
  재부팅 → RaiDrive 설치 프로그램으로 복구/재설치 →
  WinFsp가 없는 경우 FileHub 설정에서 2025 정식판 설치 순서입니다.
- 주황색 하단 메시지는 2.2 Beta 감지 시
  "WinFsp 베타 2.2 감지 · RaiDrive 보호: 수동 복구 필요"로 표시됩니다.
  WinFsp 2.1.25156 정식판에서는 알림을 숨깁니다.
- WinFsp 2025 정식판에는 2026 베타에서 수정된 CVE-2026-3006 및
  CVE-2026-7162 보안 패치가 포함되지 않았을 수 있습니다.
  안정성과 RaiDrive 호환성 우선의 복귀이므로 보안 위험을 인지하고 사용하세요.
- 실제 RaiDrive 동작과 파일 잠금은 사용자 PC 실기기에서 최종 확인해야 합니다.

## v1.3.95 Google WinFsp 네트워크 충돌 · NAS 포트 오류 · 종료 메뉴 간소화

- Google Drive는 OAuth가 아니라 Windows WinFsp FUSE의
  Status=80070050, mountpoint not available 오류로 실패했습니다.
  기존 O:가 사용 중일 때 Z:/M:으로 자동 변경해도 실패한 것이
  로그에 확인됩니다. Google 드라이브 문자를 자동으로 바꾸거나
  설정에 저장하지 않고 충돌 원인을 안내합니다.
- Google WinFsp network-mode의 UNC 서버 이름이 이전 실패 연결과
  중복될 가능성을 막기 위해 **연결 시도별 고유 네트워크 이름**을
  생성합니다. 정확한 FileHub 프로필 GUID로 소유권 확인을 수행해
  다른 제품의 드라이브나 NAS 데이터를 강제 종료하지 않습니다.
- Google WinFsp 80070050 충돌은 자동 재시도를 15분간 보류합니다.
  실제 회사 PC의 충돌 해결 여부는 업데이트 후 실기 검증이 필요합니다.
- 오름 NAS는 http://ormshop.iptime.org:5006/ 에서 PROPFIND EOF입니다.
  Synology WebDAV HTTPS 표준 포트 5006에 HTTP 사용이 설정되면
  연결 전에 차단하고 HTTPS 사용 및 인증서 도메인 일치를 안내합니다.
  TLS 검증을 끄거나 NAS 주소를 임의 변경하지 않습니다.
- **트레이의 비상 종료 메뉴 2개와 NAS 개별 비상 종료 메뉴를 삭제**
  했습니다. 기존 연결 해제와 프로그램 종료가 접속 성공 전
  실패 프로세스를 자동 정리합니다. 정상 사용 중인 연결은 업로드
  안전 처리를 유지하고 일반 프로그램 종료는 8초로 제한합니다.
- v1.3.94에서 잘못 변경했던 **상단 X 버튼**은 다시 트레이로 숨기는
  동작으로 복원했습니다. 트레이 아이콘 더블클릭으로 창을 열고,
  트레이의 [프로그램 종료]를 선택한 경우에만 실제 종료합니다.
  최소화 버튼도 기존처럼 트레이로 숨깁니다.

## v1.3.94 접속 실패 즉시 강제 정리 · 종료 불가 해결 · 탐색기 가시성

- **접속이 한 번도 성공하지 않은 드라이브**는 업로드/편집 세션과
  구분합니다. rclone·잠금 브리지가 실행됐다가 첫 폴더 검사 전에
  연결 실패하면 이 FileHub가 직접 시작한 해당 프로세스만 강제로
  종료하며, 연결 기록과 본인 소유 탐색기 등록을 정리합니다.
  사용자에게 불필요한 업로드 대기 경고를 반복하지 않습니다.
- **연결 중단**을 클릭했을 때도 첫 마운트 검사 통과 전이라면
  잠금 브리지 정상 QUIT이나 연결용 세마포어를 기다리지 않고
  실패한 연결을 즉시 중단합니다. 자동 재연결은 해당 세션에서
  일시 중지되고 사용자가 명시적으로 재연결을 누르면 해제됩니다.
- **일반 프로그램 종료/상단 X**는 전체 8초 예산으로 종료합니다.
  미연결 실패 프로세스는 강제 종료하고 정상 연결은 짧게 안전
  해제를 시도합니다. 정상 연결이 응답하지 않으면 그 백엔드와
  로컬 VFS 캐시는 그대로 보존하지만 프로그램 GUI 종료 자체를
  막지 않습니다. OTA 설치만은 기존 엄격한 안전 해제 정책 유지.
- **WebDAV HTTPS**에서는 WinFsp 드라이브를 만들기 전에 TLS
  서버 인증서의 호스트명/유효기간/인증서 체인을 확인합니다.
  ormshop.iptime.org 주소로 접속했는데 NAS가
  ormshop.synology.me 인증서를 보내는 경우 연결을 시작하지
  않고 정확한 주소 수정 안내를 표시합니다. TLS 검증 우회는
  지원하지 않으며, NAS가 두 호스트 모두 쓸 경우 SAN 인증서를
  올바르게 설정해야 합니다.
- **Google Drive O:**에서 앱 내 연결 표시와 Windows 탐색기
  표시가 어긋나는 경우를 구별합니다. 약 55초 간격으로 실제
  루트 조회(6초 제한)와 Windows 탐색기 Shell 표시(4초 제한,
  독립 STA 스레드)를 확인하며, 접근 가능한 드라이브만 탐색기에
  재통지합니다. 기존 rclone, RaiDrive, 캐시를 재설정하지 않습니다.
  카드의 점 세 개 메뉴에서도 탐색기 표시를 재확인할 수 있습니다.
- 실제 회사 NAS 인증서, 탐색기 갱신 및 파일 쓰기 상태는
  회사 테스트 PC에서 최종 확인해야 합니다.

## v1.3.93 서버 기본 잠금 연결 먹통·비상 종료 개선

- WebDAV '서버 기본 잠금'은 **실험 기능**입니다. 연결을 실행하기 전에
  실제 서버에 고유 임시 검사 파일을 만들어 RFC4918 LOCK/UNLOCK,
  토큰 없는 두 번째 쓰기의 거부, 정당한 토큰 쓰기, 검사 파일 삭제까지
  확인합니다. 검사 제한시간은 30초이며, 미지원/오류 서버에서는
  rclone/WinFsp 연결을 시작하지 않고 일반 파일잠금 브리지 이용을
  안내합니다. 검사 파일 삭제가 실패했다면 진단 메시지를 확인하세요.
- 서버 잠금 검사 실패 후 자동 재연결은 10분간 재시도하지 않습니다.
  실제 NAS의 LOCK 호환성은 테스트해야 하며, 오프라인 코드 검사만으로
  서버별 정상 연결을 보증하지 않습니다.
- WinFsp 가상 드라이브 존재 여부의 동기 확인을 UI 경로에서 제거하고,
  연결 중 폴더 존재 확인은 단일 백그라운드 작업으로 실행합니다.
  파일시스템 콜백이 650ms 넘게 응답하지 않으면 UI를 붙잡지 않으며,
  대기 중인 조회가 끝나기 전에는 중복 작업을 생성하지 않습니다.
- 일반 연결 해제/프로그램 종료는 기존 업로드 안전 검사를 계속 지킵니다.
  다만 브리지 충돌 또는 WinFsp 콜백 정지 등으로 정상 종료가 실패하면
  **NAS 카드 우측 점 세 개 → '비상 연결 종료 · 데이터 손실 위험'**
  메뉴에서 해당 FileHub 소유 연결만 명시적으로 중단할 수 있습니다.
- **트레이 메뉴**에는 '비상 종료 · 창만 닫고 연결 보존' 및
  '비상 종료 · FileHub 연결 강제 중단' 두 경로를 추가했습니다.
  두 번째는 사용자의 확인을 받고 FileHub가 직접 실행한 rclone과

## v1.3.86 Synology 공유 폴더 다중 선택

- DSM 주소, 계정, 비밀번호를 입력한 뒤 **목록 불러오기 · 다중선택**을 누르면 DSM File Station의 SYNO.FileStation.List v2 list_share API로 현재 계정이 볼 수 있는 공유 폴더 목록을 읽습니다.
- 예: /01자료, /02자료, /video를 한 번에 체크해 저장할 수 있습니다. 저장된 폴더 목록은 NAS 연결별로 유지됩니다.
- **NAS 파일 / 폴더 탐색** 버튼으로 선택한 공유 폴더 내부를 탐색하여 파일·폴더를 선택할 수 있습니다. 탐색하는 동안 인증 세션을 재사용하므로 폴더를 열 때마다 로그인하지 않습니다.
- 공유 링크 생성·목록·해제는 체크된 공유 폴더 내부로 한정됩니다. Windows 드라이브 경로가 여러 DSM 공유 폴더 중 어디에 해당하는지 안전하게 판별할 수 없으면 추측하지 않고 DSM 파일 탐색을 안내합니다.
- 기존 v1.3.85의 단일 ShareRoot 설정은 새 ShareRoots 목록이 비어 있을 때 계속 읽습니다. 새로 선택하면 ShareRoots 목록으로 저장합니다.
- OTP 6자리 입력 방식을 유지합니다. 실제 DSM 2단계 인증 및 NAS 실기기 링크 생성은 별도 검증이 필요합니다.

## v1.3.86 시놀로지 공유 링크 오류 진단 및 신뢰 PC 인증

- 이전에는 공유 링크 생성 때마다 DSM에 새로 로그인하면서 매번 OTP를 요청했습니다.
- 이제 DSM 로그인에 첫 OTP와 함께 **이 PC 신뢰**를 선택하면 공식 enable_device_token / device_name 필드를 보내고, DSM이 반환한 did를 Windows 자격 증명 관리자에 보호 저장합니다.
- 이후 DSM 로그인에는 저장한 device_id와 device_name을 전송하므로, 서버가 신뢰를 유지하는 동안 링크 생성·목록·탐색을 반복해도 OTP를 다시 입력하지 않습니다.
- 인증이 만료·철회되거나 DSM 보안 설정이 변경되면 OTP 입력창을 다시 표시합니다. 신뢰를 해제하면 저장된 PC 기기 ID를 지웁니다. OTP 숫자는 저장하지 않습니다.
- 토큰을 NAS 주소, DSM 사용자, FileHub 연결 프로필별로 구분하므로 다른 계정이나 NAS에 전달하지 않습니다.
- 생성 대상이 비어 있으면 오류가 나기 전에 DSM 파일/폴더 탐색으로 대상을 선택하도록 안내합니다. 공유 링크 API가 거부하면 API 이름·메서드·오류 코드와 점검 항목을 표시합니다.
- 실제 DSM NAS에서 인증·기기 신뢰·링크 발급 결과는 실사용 검증이 필요합니다. Windows 컴파일 및 오프라인 정책/UI 테스트 성공은 서버 호환성의 증거가 아닙니다.

## v1.3.87 Excel 반복 저장 외부 변경 오인 방지

- WebDAV 폴더 자동감시기가 사용자의 Excel 저장으로 업로드된 파일을 외부 변경처럼 WinFsp Notify(Modified)로 다시 통보하는 원인을 루프백 WebDAV+실제 Excel 2회 저장 테스트에서 확인했습니다.
- 변경한 LockBridge는 성공한 Excel 임시파일→원본 rename의 길이와 SHA-256을 로컬 영수증으로 기록하고, 감시기가 NAS에서 읽은 파일의 크기 및 SHA-256이 일치하는 경우에만 자기 저장 알림 한 건을 제외합니다.
- 원격 파일이 다르거나 검증 실패, 알 수 없는 경로, 다른 PC의 수정/삭제는 기존 알림을 유지합니다. 다른 사용자의 실제 동시 수정을 감추기 위해 감시기 전체를 중단하지 않습니다.
- 수정 전에는 Excel 저장 직후 매번 DIRWATCH CHANGE Modified가 발생했지만, 수정 후에는 두 번 모두 OWN_SAVE_RECONCILED가 기록됐습니다. 두 저장본의 내용과 원본 서버 파일 무결성을 실제 Excel에서 확인했습니다.
- 별도 WebDAV 클라이언트 파일 생성/수정/삭제/하위폴더 변경 이벤트는 모두 검증했습니다.
- 실제 사용자의 Synology 장치/여러 PC가 동시에 편집하는 환경은 추가 확인이 필요하며, 서버 종류별 동시 저장 충돌을 완전히 해결했다고 주장하지 않습니다.

## v1.3.87 Synology 공유 링크 UI 분리

- 메인 앱의 Synology 공유 설정에는 DSM 주소/계정/저장된 암호, 2FA 신뢰, 공유 폴더 다중선택, 기본 링크 만료일과 선택적 링크 암호만 둡니다. 링크 암호와 DSM 암호 및 기기 토큰은 Windows 자격 증명 관리자에 저장하고 설정 JSON에는 보관하지 않습니다.
- Windows 탐색기 파일/폴더 우클릭 메뉴를 선택하면, 저장된 연결 프로필을 찾고 해당 파일의 DSM 경로를 매핑하여 SYNO.FileStation.Sharing.create를 자동 호출합니다.
- 성공 시 작은 창에 공유 URL과 **링크 복사** 버튼만 표시합니다. 설정창을 다시 띄우거나 링크 생성 버튼을 한 번 더 누를 필요가 없습니다.
- DSM 신뢰 기기가 만료됐다면 보안상 OTP를 다시 요구합니다. 경로나 계정 설정이 잘못됐다면 작은 창에서 설정으로 이동할 수 있습니다.
- 다중 공유 폴더 경로를 안전하게 구분할 수 없다면 임의 폴더를 선택해 공유 링크를 만들지 않습니다. 공유 링크 발급은 사용자 NAS에서 검증해야 합니다.

## 앞으로의 PC 소스 자동 갱신

- NuGet 라이브러리 버전은 루트의 **Directory.Packages.props**에서 중앙 관리합니다. Windows 본체와 LockBridge의 SSH.NET, FluentFTP 버전이 한 파일에서 결정됩니다.
- Dependabot이 매주 월요일(한국 시간) GitHub의 새 버전을 확인하고 PC 전용 pc/windows를 대상으로 **의존성 수정 커밋이 포함된 PR**을 생성합니다.
- PC 의존성 PR에는 별도의 Windows 빌드·정책 테스트 워크플로가 실행됩니다. 테스트 실패 시 기존 버전을 유지하며, 메이저 변경·런타임/드라이버 업데이트도 검토 후 병합합니다.
- winfsp.net은 대응 WinFsp MSI와 같은 버전/해시를 함께 검증해야 하므로 Dependabot 단독 업데이트 대상에서 제외했습니다. rclone과 TeraBox 확장도 공식 SHA-256 고정 상태를 유지합니다.
- **빌드 때마다 무조건 최신 버전을 받아 교체하거나 자동으로 정식 릴리즈를 게시하지 않습니다.** 검증된 PR을 병합한 다음 PC 앱 버전 태그를 증가시켜 전체 테스트를 통과하면 그때 새로운 Windows OTA 릴리즈로 반영합니다.
- GitHub Dependabot 설정은 GitHub가 기본 브랜치 main에서만 읽으므로, .github/dependabot.yml은 Android 소스 변경 없이 main에도 함께 설치해야 PC 자동 PR이 활성화됩니다.
