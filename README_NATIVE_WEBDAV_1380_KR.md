# NAS Mount v1.3.80 — WebDAV 서버 기본 잠금 (선택형 시험 배포)

## 문제

NAS Mount v1.3.78은 기존 다중 PC 동시 편집 잠금 협상을 위해
`문서.xlsx.nasmount.lock` 폴더를 실제 NAS 서버에 만든다.
NAS Mount 자체 파일 목록에서는 숨기지만 다른 클라이언트는 볼 수 있다.

## v1.3.80 변경 내용

- **서버 기본 잠금 선택 기능:** WebDAV 프로필의 파일잠금 모드 아래에서
  `서버 기본 잠금 (폴더 없음)` 옵션을 직접 선택하면 RFC 4918 LOCK을 사용한다.
  기존 연결 프로필은 기본 OFF이며 자동 변경하지 않는다.
- **로컬 HTTP 중계:** rclone v1.76.0의 WebDAV 원격 URL을 무작위
  127.0.0.1 포트 및 긴 난수 경로로 된 `NativeWebDavGateway`에 연결한다.
  rclone의 실제 PUT/MOVE/PROPPATCH 요청을 중계하면서 파일별
  `If: <실제 NAS 파일 URI> (<Lock-Token>)` 조건을 주입한다.
  별도의 `*.nasmount.lock` 폴더를 생성하지 않는다.
- **파일잠금 브리지 연동:** WinFsp 쓰기 핸들을 열 때 브리지가 인증된
  로컬 잠금 제어 API를 통해 서버 LOCK을 얻고, 닫은 뒤 rclone
  업로드 큐 상태가 안전할 때에만 UNLOCK한다. 남은 잠금은 주기적으로
  갱신하며, 만료가 임박하거나 갱신 실패 시 파일 쓰기를 차단한다.
- **엑셀 원본 보존:** Excel이 기존 원본을 백업 `.tmp`로 옮기려고 할 때
  일반 WebDAV MOVE는 원본의 서버 LOCK을 잃게 된다. 이 경우
  서버 원본을 계속 보호하면서 백업을 생성하도록 COPY로 처리한다.
  이후 새로운 `.tmp`를 원본으로 MOVE할 때 목적지 LOCK 토큰을 보낸다.
  변환이 안전하게 적용되지 않는 이름 변경 및 Office 원본 DELETE는
  명시적으로 거부하여 중도 데이터 손실을 방지한다.
- **구버전 혼용 차단 시도:** 구버전 `.nasmount.lock` 폴더 존재를 HEAD로
  확인할 수 없거나 이미 존재하면 새 잠금을 허용하지 않는다. 그러나
  **구버전이 나중에 새 잠금의 존재를 알아채지는 못하므로** 다른 PC의
  기존 v1.3.78과 같은 NAS 문서를 혼합 편집하면 안 된다.

## 검증

- `dotnet build NASMount.csproj -c Release`: 성공.
- `dotnet build LockBridge/LockBridge.csproj -c Release`: 성공.
- `--native-webdav-lock-lab-test`: 23개 통과.
- `--native-webdav-gateway-lab-test`: 30개 통과.
- 실제 배포 rclone **v1.76.0 실행 파일을 중계 계층에 연결**하여
  256KiB 이진 문서 업로드 및 서버 측 바이트 동일성 확인.
- 실제 로컬 HTTP를 이용한 두 연결의 잠금 충돌, 2MiB PUT,
  토큰 없는 PUT 거부, Office 원본 백업 COPY 후 잠금 유지,
  임시파일의 원본 MOVE, 잠금 해제, 한글 `11월매출.xlsx`
  경로의 토큰 매칭, 잠금 폴더 생성 0건.
- `--self-test` 및 잠금 브리지 로컬 WinFsp callback 테스트,
  0바이트 Excel 덮어쓰기 거부, 기존 파일명 대소문자 유지,
  Office 소유자 표시 테스트 통과.

## 중요 — 시험 배포 한계

**아직 실제 Synology/NAS에서 Excel의 열기→수정→저장 및 두 대의 실제
PC 동시 접근 테스트가 끝나지 않았다.**
서버 WebDAV가 LOCK/UNLOCK을 지원하는지, 일부 NAS에서 COPY
및 LOCK 토큰을 구현한 방식이 호환되는지 추가 검증이 필요하다.
서버가 지원하지 않으면 안전을 위해 문서 저장을 거부할 수 있다.
또한 Excel 백업/원본 저장 절차가 버전별로 다르면 별도 검증이 필요하다.

1. **회사 실문서/현재 업무 중인 드라이브에서 새 잠금을 처음 켜지 않는다.**
2. 다른 PC에서도 모두 새 모드로 전환하기 전에는 실문서 동시
   편집이 안전하다고 판단하지 않는다.
3. 먼저 별도 시험용 WebDAV 공유/테스트 파일과 백업으로 2PC 테스트한다.
4. 문제가 있으면 해당 프로필 연결을 해제한 뒤 `서버 기본 잠금`
   체크를 끄고 기존 협력 잠금 방식으로 되돌릴 수 있다.
5. 새 모드에서 **Office 원본 삭제는 안전을 위해 차단**될 수 있다.
6. 동일한 잠금 서버에 대해 old/new 클라이언트가 혼재한 동안에는
   서로의 잠금 표시가 완전히 호환되지 않는다.

이 배포본은 실사용 검증 전의 **기능 통합 시험용 v1.3.80 베타**이며,
기존 실행 중인 v1.3.78을 자동 교체하지 않는다.
