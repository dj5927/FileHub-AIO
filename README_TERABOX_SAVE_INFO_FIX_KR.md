# NAS Mount Android v0.1.34 - TeraBox 문서 저장 및 덮어쓰기 응답 수정

## 사용자 기기에서 보고된 증상

- v0.1.33에서 TeraBox 읽기는 되지만 기존 Markdown 파일을 편집한 후 저장할 때
  "TeraBox 파일 작업 응답에 오류 코드와 성공 확인 정보가 없습니다" 오류 발생.
- 이 문구는 TeraBox 서버에서 직접 발행한 오류가 아니라 NAS Mount 앱이 만든 문구.

## 확인된 코드 문제

- 기존 원격 파일을 저장하면 앱은 임시 파일을 업로드하고, 서버 측 COPY로 원본 파일을
  교체한 후 임시 파일을 휴지통으로 이동시킴.
- filemanager 및 비동기 taskquery의 최상위 응답은 errno=0으로 확인하지만,
  info/list 배열 안에 든 개별 항목에도 무조건 errno가 있어야 한다고 검사했음.
- 서버의 개별 항목이 path, fs_id 등 메타데이터만 담으면 전체 성공에도
  앱이 "파일 작업 응답" 오류를 던지는 코드 경로를 확인함.

## 수정 사항

- 전체 응답에는 기존 errno=0 엄격 검사를 유지.
- 개별 항목에 errno/error_code가 있으면 0이 아닌 값을 계속 오류로 판단.
- 개별 항목이 파일 메타데이터만 담고 있어 오류 코드가 없는 경우,
  이미 성공 확인된 최상위 응답을 기준으로 처리.
- 개별 항목의 error/error_msg, success=false, status=failed/error는 계속 실패로 처리.
- 기존 TeraBox 읽기, MYBOX, WebDAV, SMB, FTP, SFTP, 폴드 UI, 동영상 플레이어는 변경하지 않음.

## 검증

- 수정 전 새 테스트의 정상 정보 항목 사례 2건이 기존 코드에서 실패함을 재현.
- 수정 후 파일 복사·비동기 작업 상태, 개별 항목 오류 코드 차단,
  문서 덮어쓰기 임시 파일 업로드→COPY→정리 전체 흐름 등 새 테스트 6건 통과.
- 전체 JUnit 241/241 성공, lintDebug, lintVitalRelease, assembleRelease 성공.
- APK v2 서명 검증, 기존 서명과 동일, Y: 배포본 SHA256 대조 완료.

## 실제 검증이 필요한 사항

Android 실기기와 사용자의 TeraBox 계정은 개발 환경에 연결되지 않음.
실제 TeraBox 서버 업로드 성공 여부는 이 버전 설치 후 확인 필요.

기존 앱 삭제 없이 덮어 설치하고 중요하지 않은 작은 TXT/MD 문서 저장을 우선 시험.
기존 원본 내용이 유지되는지, 변경 내용이 다시 열었을 때 남아 있는지 확인.
실패하면 새로운 오류 문구/화면을 확인하고 다음 단계 원인을 추적해야 함.
