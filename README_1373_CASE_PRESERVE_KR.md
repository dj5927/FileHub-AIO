# NAS Mount v1.3.73 — Office 파일명 대소문자 보존

## 확인된 현상

- 파일잠금 브리지로 연결한 WinFsp 네트워크 드라이브에서 기존 `LabActual.xlsx`를 Excel로 저장한 뒤, 서버의 실제 이름이 `LABACTUAL.XLSX`로 바뀌는 문제가 재현되었습니다.
- 동일한 로컬 WebDAV 서버를 일반 rclone 드라이브로 연결하면 기존 이름 `LabActual.xlsx`가 유지되었습니다. 즉, 확장자가 대문자로 바뀌는 문제는 테스트한 환경에서 **NAS Mount 파일잠금 브리지의 Excel 저장 시 이름 변경 처리**와 관련되어 있었습니다.

## 수정 내용

1. Excel이 기존 문서를 임시 백업파일로 옮기기 전에, NAS에 존재하는 원본 파일명의 **정확한 대문자·소문자 형태**를 읽기 전용으로 확인하여 짧게 보존합니다.
2. Excel의 임시파일을 최종 문서로 바꾸는 원자적 이름 변경에서 기존 원본 파일명의 표기를 복원합니다. 이전에 대문자 확장자를 사용하던 파일도 그대로 유지합니다.
3. 이전에 없던 새 Office 문서의 임시파일→최종파일 저장에서는 확장자를 소문자로 기록합니다.
4. 기존 파일의 내용이나 확장자를 사후에 별도 수정하는 재전송 작업은 추가하지 않았습니다. 실패한 저장에서 임의로 원본을 덮어쓰지 않으며, 기존 Excel 0바이트 방지 검사를 유지합니다.
5. WebDAV 폴더 실시간 갱신과 잠금 브리지의 별도 읽기·쓰기 권한, 파일잠금 및 안전한 드라이브 해제 로직은 유지했습니다.

## 실제 로컬 테스트 결과

| 시험 | 결과 |
|---|---|
| 수정 전 Excel 기존 파일 저장 | `LabActual.xlsx` → `LABACTUAL.XLSX` 재현 |
| 수정 후 Excel 기존 파일 저장 | `LabActual.xlsx` 유지, 내용 정상 저장 |
| Excel 다른 이름으로 저장 | `NewCase.xlsx` 유지, 내용 정상 저장 |
| 기존 구형 Excel 문서 저장 | `LabActual.xls` 유지, 내용 정상 저장 |
| 일반 rclone만 사용하는 연결 | 같은 기존 파일명 `LabActual.xlsx` 유지 |
| WebDAV 외부 클라이언트 파일 생성·수정·삭제 알림 | 루트와 하위 폴더 모두 통과 |
| NAS Mount 앱 회귀검사 | 22/22 통과 |
| 잠금 브리지 회귀검사 | 6/6 통과 |

모든 위 파일 저장 실험은 PC 내부의 **일회용 로컬 WebDAV 서버와 별도 테스트 드라이브**를 사용했습니다. 실제 사용자의 NAS 계정과 업무 파일에는 접근하지 않았습니다. 다른 Office 앱·클라우드 서비스·다중 PC 동시 편집에서의 결과는 실제 환경에서 추가 확인이 필요합니다.

## 사용 및 유지보수

- 기존 NAS Mount에서 진행 중인 업로드를 끝내고 Excel 파일을 닫은 뒤 **안전하게 연결 해제**합니다.
- `NASMount_1_3_73_CASE_PRESERVE_FULL.zip`을 기존 폴더를 덮어쓰지 않고 **새 폴더에 전체 압축 해제**하여 실행합니다.
- NASMount.exe만 교체하면 수정이 적용되지 않습니다. 반드시 함께 배포된 `tools/NASMountLockBridge.exe`, `tools/NASMountLockBridge.dll` 및 구성 파일을 유지합니다.
- 일반 rclone `v1.76.0`, TeraBox 확장 rclone `v1.76.0-extra`는 변경하지 않았습니다.
- 전체 구성 요소 이력은 `README_COMPONENTS_1373.md`와 프로그램 **환경 설정 → 엔진 · 버전 · README**에서 확인할 수 있습니다.
