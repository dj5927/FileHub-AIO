# NAS Mount Android v0.1.59 — TXT 첫 화면 지연·안내문 잔존·하단 글자 잘림

## 사용자 제보

- 히든 플레이어 (완).txt: 페이지를 나누는 중... 빈 화면이
  최초 약 10~20초 지속됨.
- SSS급 리커버리 마도사 (완).txt: 본문이 표시돼도 중앙 안내가
  사라지지 않고 계속 글자 위에 겹쳐 보임.
- 히든 플레이어 (완).txt: 마지막 1줄이 페이지 이동바 가까이에서
  잘려 보이고 다음 장으로 내용 누락 우려.

## 확인된 원인

v0.1.58까지 500만 자 이하 TXT의 페이지형은 BookPaginator가
파일 전체를 한꺼번에 StaticLayout으로 쪽수를 모두 계산한 다음
첫 페이지를 표시했습니다. 6,524페이지 같은 소설에서는
처음 화면 대기시간이 길어졌습니다. 화면 크기/글꼴/안전 여유 변경으로
재계산할 때에도 중앙 로딩 안내를 다시 표시해, 이미 읽는 중인
본문 위에 문구가 장시간 겹치는 현상이 발생했습니다.
기존 BookPageSafety의 1.3줄 안전 여유는 일부 삼성 폰트의
한국어 구절 줄바꿈에서 마지막 줄 높이를 확보하기 부족했습니다.

## 수정 사항

1. 12만 자 초과 TXT는 현재 읽는 위치 주변의 약 48,000자만
   먼저 페이지로 구성하여 곧바로 표시합니다.
   이 창은 사용자 조작에 따라 앞뒤로 이동합니다.
2. 정확한 책 전체 페이지 수는 별도 pageIndexWorker가
   백그라운드에서 계산합니다. 이 작업이 진행 중이어도
   첫 페이지, 앞뒤 페이지 넘김, 전체 퍼센트 이동이 가능하며
   본문 표시 전용 작업 대기열을 점유하지 않습니다.
3. 전체 인덱스 완료 전에는 페이지 읽기 · XX%로,
   완료 후에는 실제 전체 페이지 수와 퍼센트를 표시합니다.
   글꼴/화면 크기가 바뀐 이전 인덱스는 작업 중단 후 폐기됩니다.
4. 본문 텍스트가 화면에 한 번이라도 나타난 뒤에는
   중앙의 페이지 구성 안내를 다시 보이지 않게 합니다.
   실제 페이지 조판 실패인 경우에만 오류 안내를 표시합니다.
5. 페이지 분할은 기존 1.3줄 대신 2.35줄 이상 안전 여유 확보.
   실제 TextView 레이아웃 높이 검사 및 넘침 재조판 기능도 유지.
   이제 짧은 창 기준으로 다시 조판하므로 수천 페이지 전체
   재계산을 반복하는 속도 문제도 줄였습니다.
6. 일반 TXT는 기존 정확한 문자 오프셋 기반 독서위치/책갈피를
   유지하고, 500만 자 초과 TXT의 long 파일 분할도 유지합니다.
7. 빠른 이동 슬라이더와 하단 SeekBar는 전체 책 0~100% 글자
   위치를 기준으로 이동하도록 했습니다.
8. 페이지 창의 끝에 오면 직전 창의 마지막 문자 다음부터
   새로운 창을 열며, 뒤로 갈 때는 앞부분을 다시 읽습니다.
9. EPUB, 만화책 뷰어, TXT 세로 스크롤 모드는 기존 방식 보존.

## 테스트 및 제한

- 새 TextPageWindowTest: 책 시작/끝, 100% 지점,
  중간 위치, 48K 다음 창, 250억 자 이상 long 오프셋,
  작은 파일과 범위 밖 입력 검증.
- BookPageSafetyTest: 한국어 줄간격에서 두 줄 이상 여유 확보.
- 전체 Android Java 빌드/JUnit/Lint/서명과 Y 배포본 SHA256 검증.
- 갤럭시 폴드 실기기가 이 작업 환경의 ADB에 연결돼 있지 않아
  실제 삼성 폰트에서의 마지막 줄 표시 및 사용자가 보고한
  10~20초 초기 지연을 물리 기기로 직접 계측하지 못했습니다.
- 실제로 만화책/EPUB/TXT 원본과 책갈피는 삭제하지 않았습니다.
