# FileHub AIO Android v0.1.71 - Synology DSM 2단계 인증

## 변경 내용
- NAS 공유 폴더 목록·공유 링크 관리 중 DSM 로그인 API가 403(인증코드 필요)을 반환하면 6자리 인증코드 입력창을 표시합니다.
- DSM 404(인증코드 오류) 발생 시 코드를 다시 입력할 수 있습니다.
- 인증코드는 Synology의 공식 `SYNO.API.Auth` v6 `otp_code` 필드에 HTTPS POST로 제출합니다.
- 2단계 인증코드는 저장하지 않습니다. 매 시도 뒤 메모리 임시 필드도 비웁니다.
- 사용자가 `이 기기를 신뢰`를 선택하면 Synology가 반환한 `did`(기기 ID)를 Android Keystore 기반으로 암호화하여 저장하고, 이후 `device_id`/`device_name`으로 인증합니다.
- 신뢰 설정을 선택하지 않으면 다음 새 DSM 세션에서 인증코드가 다시 필요할 수 있습니다.
- Synology 로그인 API의 `enable_syno_token=yes`를 요청하며 DSM CSRF 토큰은 후속 API 요청 URL의 `SynoToken` 쿼리 필드로만 전송합니다. 로그인 비밀번호나 OTP는 URL에 넣지 않습니다.
- 이미 저장한 NAS 접속 설정, 다중 공유 폴더 선택, 기존 계정 정보는 유지합니다.

## 사용
1. FileHub AIO v0.1.71을 기존 앱 위에 설치합니다.
2. Synology NAS 연결 길게 누르기 → NAS 공유 링크 설정 → 공유 폴더 목록 불러오기
3. 2단계 인증코드 창에서 DSM Secure SignIn/OTP 앱의 6자리 숫자를 입력 후 `인증하고 계속`
4. 원하면 `이 기기를 신뢰`를 체크하여 이후 매번 6자리 코드를 입력하는 것을 줄일 수 있습니다.
5. 01~04 등 필요한 공유 폴더 선택 → `인증 확인 후 저장`

## 검증 및 제한
- 빌드/JVM 회귀 테스트는 실제 Synology 계정의 2FA와 독립적입니다. 휴대전화 또는 테스트 NAS 계정이 없어 실기기 로그인·보안앱 승인·링크 다운로드 성공은 검증하지 못했습니다.
- DSM 계정에서 OTP 인증 대신 앱 푸시 승인만 허용하거나 추가 보안 정책이 적용되면 별도 인증 흐름이 필요할 수 있습니다.
- 사용자가 2FA를 끌 필요가 없고, 2FA를 우회하는 백도어는 추가하지 않았습니다.
