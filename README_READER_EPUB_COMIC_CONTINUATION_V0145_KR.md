# NAS Mount Android v0.1.45
# 만화책 다음 권 / 합본 이미지 분할 / 내장 EPUB / 텍스트 스크롤 먹통 수정

## 설치

기존 설치된 NAS Mount v0.1.44 앱 위에 서명 유지 업데이트 설치.
기존 NAS 연결, 즐겨찾기, 독서용 폴더 지정 및 책갈피는 보존됩니다.

## 1. 만화책 다음 권 자동 연결

- 만화책으로 지정한 폴더에서 같은 작품의 ZIP/CBZ/RAR/CBR/7Z/CB7
  파일을 자연스러운 숫자 순서로 정렬합니다.
- 마지막 페이지에서 다음으로 한 번 더 넘기면
  "다음 만화책 이어 보기" 확인창을 보여줍니다.
- "다음 권 보기"를 누르면 앱을 벗어나지 않고 다음 압축파일을 엽니다.
- 다음 권이 없거나 파일명이 다른 작품으로 판단되면 자동 연결하지 않습니다.
- 네트워크 NAS/클라우드, 로컬 내장 저장소, SAF SD 카드의
  같은 폴더에서 열었을 때 다음 권을 찾을 수 있습니다.
- 원본 만화책은 압축해제 폴더를 만들지 않고 읽기만 합니다.
- 각 권의 독서 기록/책갈피는 별도로 보존됩니다.

## 2. 만화책 좌우 합본 스캔 자동 나눔

- 한 이미지가 두 장을 좌우로 합친 가로형 스캔이라면 자동 감지합니다.
- 접힌 휴대폰에서는 원본 한 장을 왼쪽/오른쪽 반으로 나눠
  2개의 독서 페이지처럼 스와이프해 읽습니다.
- 한국식은 왼쪽 장부터, 일본식은 오른쪽 장부터 읽습니다.
- 폴드 펼침/태블릿 화면에서는 같은 합본 이미지 2개를 재결합하는
  것이 아니라 원래의 온전한 한 장을 그대로 펼쳐 보여줍니다.
- 개별 세로 원본 이미지들은 기존처럼 펼침 화면에서 두 장 표시됩니다.
- 원본 압축파일/이미지 바이트는 절대 변경하지 않습니다.
- 만화책 설정 → "좌우 합본 이미지 자동 분할"
  - 자동 감지(기본): 가로/세로 비율 약 1.38 이상
  - 분할하지 않음
  - 민감하게 감지: 가로/세로 비율 약 1.13 이상
- 자동 검출은 이미지의 가로세로 비율에 근거하므로, 원래 한 장인
  가로 구도 그림이 합본으로 오인되면 '분할하지 않음'을 선택하세요.
- ZIP은 이미지 메타데이터 헤더를 각각 읽고, RAR/7Z는 배경 작업에서
  압축 항목을 한 번 순회해 이미지 크기를 분석합니다. 큰 압축파일은
  처음 열 때 기존보다 시간이 더 걸릴 수 있습니다.
- v0.1.44의 파일별 기존 읽던 위치는 원본 이미지 번호를 새
  좌우 분할 독서 페이지로 변환해 이어 읽습니다.

## 3. Moon+ Reader 참고, 내장 EPUB 뷰어

- 외부 앱을 호출하지 않는 기본 EPUB 리더를 새로 탑재했습니다.
- 기존 '폴더 용도 설정 → 독서용 폴더 → 텍스트책 폴더 지정'
  을 선택한 폴더와 하위 폴더의 .epub 파일을 직접 열 수 있습니다.
- 일반 EPUB2/EPUB3 OCF ZIP 구조와 container.xml, OPF manifest/spine
  순서에 따라 XHTML 본문을 읽습니다.
- CSS, 문단/이미지/SVG, 상대 리소스 경로를 앱 내부 WebView로 표시.
- 글자 크기, 줄 간격, 좌우 여백, 아이보리/흰색/세피아/야간 배경.
- 좌우 페이지 모드 또는 세로 연속 스크롤 모드, 목차별 장 이동.
- 읽던 위치 복원, 책갈피 등록/이동/삭제, 파일 목록 독서 % 표시.
- 폴드 펼침 시 페이지 모드에서 두 열 레이아웃 적용.
- 자바스크립트·외부 네트워크 링크·앱의 로컬 파일 접근은 비활성화.
- EPUB 내부 리소스만 제한된 가상 호스트로 읽고,
  EPUB 파일 전체를 외부 폴더에 풀지 않습니다.
- DRM 암호화 도서, EPUB3의 대화형 스크립트/멀티미디어 기능은
  지원하지 않습니다. 내부 이미지/스타일이 비표준인 파일은
  일부 깨질 수 있으므로 일반 EPUB2/3을 우선 사용해 주세요.
- EPUB 한 파일 512MB까지, 개별 본문 4MB 및 내부 리소스 24MB 제한.
- EPUB은 기존 TXT용 폴더 설정을 함께 이용하지만 별도의
  WebView 기반 EPUB 뷰어가 열립니다. 일반 TXT 편집기는 유지합니다.

## 4. TXT 세로 스크롤 먹통 원인 및 해결

- 원인: 이전 버전은 긴 소설 TXT를 한 개의 TextView에 넣어
  모든 글자의 줄바꿈/화면 배치를 UI 스레드에서 계산했습니다.
  이 때문에 수십만~수백만 글자 TXT에서 앱이 먹통처럼 보였습니다.
- 해결: 전체 본문은 메모리 문자열로만 보유하고,
  화면에는 최대 약 2만 4천 글자 구간만 표시합니다.
- 스크롤이 구간 끝에 가까워지면 다음/이전 구간을 교체,
  현재 보이는 글자 위치를 복원하여 계속 읽습니다.
- 다른 페이지로 직접 이동, 책갈피 이동, 페이지형/스크롤형 전환,
  다시 열기에서도 문자 위치를 유지합니다.
- 12MB 제한은 기존과 동일합니다.
- JUnit은 대용량 텍스트의 구간 계산과 범위 이탈 방지를 검증하고,
  폴드 실기기에서의 실제 스크롤 연속성/체감 속도는
  별도 확인이 필요합니다.

  SD카드 저장소 접근까지 직접 검증한 상태는 아닙니다.

- 이전 v0.1.44 APK/소스를 보존하고 별도 버전으로 배포합니다.
